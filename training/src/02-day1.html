Module 1.1 · 20 min

>Claude chat vs Claude Code

Same Claude models, very different way of working. In chat, Claude tells you what to do. In Claude Code, Claude does the work on your files and tools — and shows you what it did.

Claude chat (claude.ai, desktop & mobile apps)

"Phone a brilliant expert"

You describe the problem and paste in what's relevant. Claude answers. You copy the answer back into your files, run it, and report what happened.

Claude Code (terminal, VS Code, Desktop "Code" tab, web)

"The expert sits at your computer"

You delegate a goal. Claude reads your files, runs commands, edits what needs changing, checks its own work — and asks your permission for anything you haven't pre-approved.

The agentic loop

When you give Claude Code a task, it works through three phases that blend together — gather context, take action, verify results — repeating until the task is done. A simple question might only need the first phase; a bug fix cycles through all three many times.

What Claude Code can reach when you run claude in a folder

  • Your project: files in that folder and its subfolders (and other folders only with your permission).
  • Your terminal: any command you could run — build tools, git, package managers, scripts.
  • Your git state: current branch, uncommitted changes, recent commits.
  • Your instructions: CLAUDE.md (team or personal) and auto memory Claude keeps for itself.
  • Extensions you add: MCP connectors, skills, subagents, hooks, plugins.

Its built-in tools fall into five families: file operations, search, execution, web and code intelligence — plus tools to delegate to subagents and to ask you questions.

Not just for developers

"Coding" is in the name, but Claude Code helps with anything you can do from a command line: analysing a folder of CSVs, turning meeting notes into action lists, renaming and organising files, building a one-page HTML dashboard, drafting documentation, or researching a question across many files.

Live demo (5 min): open the same small project in claude.ai and in Claude Code. In chat, ask "what does this project do?" — it can't know without you pasting files. In Claude Code, ask the same question and point out the tool calls (Read, Glob/Grep) appearing in the transcript. Then ask Claude Code to "add a README section on how to run it" and show the permission prompt.

Key message: the model is the same family; the harness (tools + context + permissions) is what changes. People who treat Claude Code like chat (asking for snippets to paste) miss most of the value.

Alternative: run inside WSL (Windows Subsystem for Linux)

Open your WSL distribution (e.g. Ubuntu) and run the Linux installer there; launch claude inside WSL, not from PowerShell. Choose WSL 2 if you work with Linux toolchains or want Claude's sandbox (OS-level isolation), which isn't available on native Windows. WSL setups don't need Git for Windows.

Fix: 'claude' is not recognized after installing

First, close and reopen your terminal — PATH changes only apply to new windows. If it still fails, add the install folder (%USERPROFILE%\.local\bin) to your user PATH:

$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')

Close PowerShell, open a new window and run claude --version again.

Keeping it up to date

  • Native installs update automatically in the background; the new version applies next time you start Claude Code. Force it with claude update.
  • Prefer fewer surprises? Switch the release channel to stable (about a week behind) via /config → Auto-update channel.
  • Homebrew / WinGet don't auto-update: brew upgrade claude-code · winget upgrade Anthropic.ClaudeCode.
  • See what changed with /release-notes.

Installation checkpoint

Most common live blockers: (1) wrong shell — CMD vs PowerShell; (2) not opening a new terminal after install (PATH); (3) TLS-inspecting corporate proxy — needs the CA certificate from IT; (4) account without Claude Code access (free plan, or Team/Enterprise seat without the right role).

Fallbacks: Desktop app Code tab, claude.ai/code, or the in-page practice terminal. Don't let one blocked install stall the room.

Permission prompts — your safety valve

When Claude wants to do something that isn't pre-approved, it stops and asks. A typical prompt shows the exact command or file diff and offers options such as:

  • Yes — allow this one action.
  • Yes, and don't ask again — for that command or web domain in this project (saved to .claude/settings.local.json). File edits approved this way last until the session ends.
  • No (or Esc) — decline. Press Tab on Yes/No first to attach a comment telling Claude what to do instead.
Heads-up: you may start in auto mode

From v2.1.283, new terminal and VS Code sessions start in auto mode by default (if your plan, model and organisation allow it): a separate safety classifier reviews actions instead of prompting you, so you'll see far fewer prompts and risky actions get blocked.

For today's labs, switch to Manual mode so you can watch and approve each step: press Shift+Tab until the status line shows ⏸ manual mode on.

The 5-part prompt formula

Short prompts work, but the more precise you are, the fewer corrections you need. The best prompts usually contain:

1 · Goal
What outcome you want, in one sentence.
2 · Context
Where to look: @files, folders, examples to follow.
3 · Constraints
What not to touch; style; tools or libraries to use or avoid.
4 · Verification
How Claude proves it worked: tests, totals, a screenshot.
5 · Output
Where results go and in what format.
Bonus
"Ask me questions first if anything is unclear."
