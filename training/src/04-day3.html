Module 3.1 · 27 min

>Connectors: plugging Claude Code into your tools (MCP)

The Model Context Protocol (MCP) is an open standard for connecting AI tools to external systems — issue trackers, wikis, databases, design tools, browsers. Each connection is an MCP server; in Claude apps they're often called connectors.

When to add a connector

When you catch yourself copying data into the chat from another tool. Once connected, Claude reads and acts on that system directly: "Add the feature described in JIRA issue ENG-4521 and open a PR", "Update our email template from the new Figma designs posted in Slack".

Two kinds of server

Remote · HTTP

A hosted service at a URL

Notion, Sentry, GitHub, Stripe, HubSpot… Usually you sign in through your browser (OAuth), or pass a token in a header.

claude mcp add --transport http notion https://mcp.notion.com/mcp
Local · stdio

A program on your machine

Started by Claude Code as a subprocess — for things that need local access, like a browser or a database socket. Everything after -- is the command to run.

claude mcp add playwright -- npx -y @playwright/mcp@latest

Three ways connectors reach Claude Code

  1. claude mcp add … in your terminal (works the same in PowerShell, CMD, zsh and bash). Run it outside a Claude session.
  2. A .mcp.json file in the project — shared with the team through git. Teammates get an approval prompt the first time.
  3. claude.ai connectors — added at claude.ai/customize/connectors (on Team/Enterprise, by admins) appear automatically when you sign in to Claude Code with that claude.ai account. They show up in /mcp labelled as coming from claude.ai.

Plugins (later today) can also bundle MCP servers. In VS Code, type /mcp in the chat panel to add, remove, enable and authenticate servers without the terminal.

Scopes: who gets the server, where

ScopeFlagLoads inShared?Stored in
Local (default)--scope localThis project onlyNo — just you~/.claude.json (under the project)
Project--scope projectThis projectYes, via git.mcp.json in the project root
User--scope userAll your projectsNo — just you~/.claude.json (top level)

On Windows, ~/.claude.json is %USERPROFILE%\.claude.json. If the same server is defined twice, local beats project beats user beats plugin beats claude.ai connector.

Hands-on: connect your first server (no sign-in needed)

The Claude Code documentation has a hosted MCP server with full-text search over the docs — perfect for a first connection.

  1. Add it (in your terminal, not inside Claude) 
    claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
    You'll see Added HTTP MCP server claude-code-docs … to local config.
  2. Check the connection 
    claude mcp list
    Look for ✔ Connected.
  3. Use it 
    Use the claude-code-docs server to look up how to pass arguments to a skill
    Approve the first tool call if asked. The tool call is labelled with the server name — proof the answer came from the connector. (Normally you don't need to name the server; naming it just guarantees it's used.)
  4. Manage it inside a session 
    /mcp
    See status, authenticate, enable/disable or reconnect servers.
  5. Remove it when done (optional) 
    claude mcp remove claude-code-docs

Servers that need sign-in

Hosted services such as Sentry, Notion or Linear use OAuth: add the URL, then authenticate.

claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

claude mcp list shows ! Needs authentication — that's expected. Start claude, run /mcp, select the server and choose Authenticate (or run claude mcp login sentry from your shell). Servers that use a static token take it at add time:

claude mcp add --transport http github https://api.githubcopilot.com/mcp/ --header "Authorization: Bearer YOUR_GITHUB_PAT"

Status decoder

StatusMeaning / next step
✔ ConnectedReady to use
! Needs authenticationRun /mcp → Authenticate, or pass a token with --header
✘ Failed to connectServer didn't respond. claude mcp get <name> shows details; test the URL with curl -I (curl.exe -I in PowerShell) or run a stdio command directly
⏸ Pending approvalA project .mcp.json server you haven't approved — run claude to approve
⊘ Disabled for this projectTurned off — re-enable in /mcp

Using connectors well

  • Just ask. Claude picks relevant tools itself; name the server when you want to be sure.
  • Reference resources with @: analyse @github:issue://123 and suggest a fix.
  • Server prompts become commands: they appear in the / menu as /mcp__server__prompt.
  • Pre-approve trusted tools with rules like mcp__claude-code-docs__* in your allow list.
  • Context-friendly: tool definitions are loaded on demand (tool search), but each server still adds names and instructions — remove servers you don't use.
Connector security checklist
  • Only connect servers you trust. The Anthropic Directory (claude.ai/directory) lists reviewed connectors, but no MCP server is security-audited by Anthropic.
  • Servers that fetch external content (web pages, emails, tickets) can carry prompt-injection attempts. Keep an eye on what Claude does after reading them.
  • Least privilege: read-only database users, fine-grained tokens scoped to specific repositories.
  • Keep tokens out of git: in .mcp.json use ${API_KEY} environment-variable expansion instead of pasting secrets.
  • Check with your organisation before connecting client systems; admins can allow-list or block servers centrally.
Troubleshooting connectors
  • /mcp says "No MCP servers configured" — you added a local-scope server from a different folder. Re-add it here, or use --scope user.
  • Edited .mcp.json but nothing changed — Claude Code reads it at startup; exit and restart. If you previously rejected it: claude mcp reset-project-choices.
  • Timeout on first start — npx may still be downloading. Raise the limit: MCP_TIMEOUT=60000 claude$env:MCP_TIMEOUT = "60000"; claude.
  • Connected but no tools — usually a missing environment variable (API key). Pass --env KEY=value when adding.
  • "Server already exists" — remove it first (claude mcp remove <name>) or pick another name.
  • A claude.ai connector is missing — run /status: connectors only load when you're signed in with a claude.ai subscription (not an API key or cloud provider).

Demo order: (1) add the docs server live and ask it a question; (2) show /mcp; (3) show a claude.ai connector if your org has one configured; (4) talk through the security checklist. Don't connect real client systems in a training room.

Module 3.2 · 12 min

>Skills: turn repeatable work into your own slash commands

A skill is a folder with a SKILL.md file: a short description (when to use it) plus instructions (what to do). Type /skill-name to run it — or let Claude load it automatically when your request matches the description.

Where skills live
  • Project (share via git): .claude/skills/<name>/SKILL.md
  • Personal (all your projects): ~/.claude/skills/<name>/SKILL.md%USERPROFILE%\.claude\skills\<name>\SKILL.md
  • Older custom commands in .claude/commands/name.md still work the same way.
Why skills beat copy-pasted prompts
  • Consistent results — the same checklist every time
  • Shareable — commit to the repo, colleagues get /your-skill
  • Cheap — only the description sits in context until the skill runs

Anatomy of a skill

---
name: weekly-status
description: Drafts a weekly status update from recent work. Use when the user asks for a status report or weekly update.
disable-model-invocation: true
---

Draft this week's status update for $ARGUMENTS.

1. Read notes/ and any files changed in the last 7 days
2. Summarise progress under: Done · In progress · Risks & issues · Next week
3. Keep it under 200 words, plain English, Australian spelling
4. Flag anything you're unsure about instead of guessing
5. Save it to reports/status-YYYY-MM-DD.md and show me the result
PieceWhat it does
nameThe command you type (/weekly-status). Defaults to the folder name.
descriptionTells Claude when the skill applies — write it like a trigger: "Use when…"
disable-model-invocation: trueOnly you can run it — use for anything with side effects (deploy, send, commit)
user-invocable: falseOnly Claude can load it — background knowledge, not a command
allowed-toolsPre-approves tools while the skill runs, e.g. Bash(git add *) Bash(git commit *)
$ARGUMENTS · $0, $1…Whatever you type after the command (/weekly-status Project Atlas) — all of it, or by position
!`command`Runs a shell command first and inlines its output (e.g. !`git diff HEAD`)

Run /skills to list what's available, and /reload-skills after adding one mid-session. Easiest of all: ask Claude — "create a /weekly-status skill for this project that …".

Demo (5 min): ask Claude to create a small skill from the anatomy example, open the SKILL.md it wrote, then run it with an argument. Point at the description line: it decides when Claude loads the skill on its own.

Watch for: a skill folder in the wrong place (it must sit directly under .claude/skills/, with the file named exactly SKILL.md), and a new skill not appearing in the session until /reload-skills is run.

>Subagents, hooks, plugins & output styles

Four more ways to shape Claude Code. You don't need them on day one — add each when its trigger shows up.

When this happens…Add this
Claude gets a convention wrong twiceCLAUDE.md line
You keep typing the same prompt to start a taskA skill
You keep copying data in from another toolAn MCP connector
A side task floods the conversation with output you won't reuseA subagent
Something must happen every time, no exceptionsA hook
You want answers in a different voice or format all sessionAn output style
A second project needs the same setupPackage it as a plugin

Subagents: helpers with their own context

A subagent works in a separate context window and returns only a summary — great for research that reads many files. Claude Code has built-ins (Explore for fast read-only searching, Plan for planning research, general-purpose for multi-step work) and delegates to them automatically. You can also ask:

use a subagent to review reports/analysis.md against the raw data and report any numbers that don't match

Custom subagents are Markdown files in .claude/agents/ (project) or ~/.claude/agents/ (personal). The easiest way to make one is to ask Claude to create it:

---
name: security-reviewer
description: Reviews code for security vulnerabilities
tools: Read, Grep, Glob, Bash
model: opus
---
You are a senior security engineer. Review code for injection flaws,
auth problems, secrets in code and insecure data handling.
Give specific line references and suggested fixes.

Hooks: guaranteed automation

Hooks run your own command at fixed moments — before or after a tool runs, when Claude needs your input, when a session starts or stops. Unlike instructions, they always fire. Classic uses: auto-format after every edit, block edits to protected files, notify you when Claude is waiting.

Add to %USERPROFILE%\.claude\settings.json — a dialog pops up when Claude needs you:

{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "powershell.exe -Command \"[System.Reflection.Assembly]::LoadWithPartialName('System.Windows.Forms'); [System.Windows.Forms.MessageBox]::Show('Claude Code needs your attention', 'Claude Code')\""
          }
        ]
      }
    ]
  }
}

Add to ~/.claude/settings.json — a desktop notification appears when Claude needs you:

{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code needs your attention\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}

No notification? Run osascript -e 'display notification "test"' once, then allow notifications for Script Editor in System Settings → Notifications.

Check it with /hooks (read-only browser). If your settings file already has a hooks key, add the event alongside the existing ones. Or simply ask: "write a hook that notifies me when you need input".

Hooks run with your permissions

A hook is a command on your machine. Only add hooks you understand, and review hooks in any repository you clone — a folder's hooks only run after you trust it.

Plugins: install a whole setup at once

Plugins bundle skills, subagents, hooks and MCP servers into one installable package. Run /plugin to browse marketplaces (including Anthropic's official one) and install. Example from the docs:

/plugin install mcp-server-dev@claude-plugins-official

If the marketplace isn't found, add it first: /plugin marketplace add anthropics/claude-plugins-official. Plugin skills are namespaced, e.g. /mcp-server-dev:build-mcp-server. Only install plugins from sources you trust.

>Beyond the terminal

Same engine everywhere: your CLAUDE.md, settings and MCP servers work across all surfaces. Pick the one that fits the moment.

VS Code power moves

Point at code
Select lines and press to insert @file.ts#5-10. Claude also sees your current selection and open file automatically.
Review diffs properly
In Manual mode edits open side-by-side; accept or reject per change, or edit the proposal before accepting.
Comment on plans
In Plan mode the plan opens as a Markdown document you can annotate inline before Claude starts.
Rewind from any message
Hover a message → fork the conversation, rewind code, or both.
Parallel conversations
Open in New Tab / New Window. A blue dot = permission waiting; orange = finished while hidden.
Terminal output as context
Reference @terminal:name to give Claude a terminal's output without copy-paste.

Prefer the terminal look inside VS Code? Enable the extension's Use Terminal setting, or just run claude in the integrated terminal (it connects to the editor for diffs and selections; from an external terminal run /ide).

Desktop, web and mobile

Desktop app
Code tab with visual diffs and side-by-side sessions; Local, Cloud, SSH and WSL environments. Hand over a terminal session with /desktop.
Web · claude.ai/code
Cloud sessions on your GitHub repos that keep running when you close the laptop. Start one from the terminal with claude --cloud "task"; pull it back with /teleport.
Phone
Run /remote-control to continue a local session from the Claude mobile app or a browser — files and execution stay on your machine.

Automation: Claude without the chat

Print mode (-p) runs one task and exits — perfect for scripts, scheduled jobs and CI.

# one-off question
claude -p "explain what this project does"

# pipe data in
cat error.log | claude -p "explain the root cause of this error"

# structured output for scripts
claude -p "list every TODO comment in this folder" --output-format json

# limit what an unattended run may do
claude -p "fix the lint errors in src/" --allowedTools "Read,Edit"
# one-off question
claude -p "explain what this project does"

# pipe data in
Get-Content error.log | claude -p "explain the root cause of this error"

claude -p "list every TODO comment in this folder" --output-format json

GitHub
/install-github-app sets up the Claude GitHub App and Actions so teammates can mention @claude on issues and pull requests.
Schedules
/schedule creates cloud routines (run even when your computer is off); /loop 10m … repeats a check while your session is open.
Parallel work
claude -w feature-x starts a session in its own git worktree so parallel edits don't collide; /background detaches a session and claude agents monitors them all.
Keep going until done
/goal all tests pass keeps Claude working across turns until the condition is met.

Demo by audience: for VS Code users, select lines to insert an @file#lines reference, then accept a side-by-side diff change by change. For everyone else, show the Desktop app's Code tab or a session on claude.ai/code.

Watch for: people who installed only the VS Code extension expecting claude to work in any terminal. The extension bundles its own copy, which isn't on PATH; install the CLI too if they want both.

Capstone · 30 min

Build a reusable "client-ready insights" workflow

Goal: combine everything — plan mode, verification, CLAUDE.md, permissions, a connector and your own skill — into a workflow you could hand to a colleague.

Steps

Success criteria
  • Outputs exist and their numbers were verified two ways
  • /insights <file> works from a fresh session
  • CLAUDE.md carries your house style; .env is denied; pushes need approval
  • You can explain which feature handled which part of the job

Pace it: roughly 5 minutes to plan, 10 to build and verify, 8 for the skill, 5 for guard rails and the connector, 2 for show and tell. Call time at each boundary; unfinished steps are fine as long as everyone reaches the skill step.

Common snags: the docs connector removed in 3.1 and not re-added (re-run the claude mcp add command from 3.1), and /insights not appearing until /reload-skills is run.

Show and tell: pick two people whose skill descriptions differ and ask the room which one Claude would trigger on more reliably, and why.
